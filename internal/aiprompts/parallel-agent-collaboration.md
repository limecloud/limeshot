# 并行开发协作协议

状态：`current`

## 目标

允许多个 Agent、终端或开发者在同一工作树并行推进，同时避免覆盖、误暂存、误删除和把未知改动混入当前候选。

## 开始前

1. 读取 `git status --short`、相关文件 diff 和当前执行计划。
2. 声明本轮窄写集、明确排除项与验证范围。
3. 已脏且与任务无关的文件视为他人所有，不格式化、不回滚、不暂存。
4. 目标文件已经被修改时，先读完整 diff；能增量协作则继续，无法判断归属才请求用户决策。

## 执行中

- 只修改声明写集；需要扩展时先更新执行计划。
- 不用 `git checkout --`、`git reset --hard`、清理命令或生成器覆盖未知改动。
- 不杀死来源不明的 dev server、Electron、测试或构建进程。
- 生成物写入仓库既有输出目录；不要把临时探针和下载物留在 tracked 路径。
- 发现并行新改动时重新读取状态并追加排除项，不把它们当成自己的 diff。

## 提交与交接

- 用户未明确要求时不 commit、push、tag 或创建分支。
- 需要提交时使用显式文件清单，提交前复核 staged diff；禁止用 `git add -A` 吞入排除项。
- 收尾列出本轮写集、排除项、验证、未验证原因和工作树剩余改动。

冲突无法安全合并时，保持双方改动原样，停止编辑冲突文件并说明精确路径与阻塞原因。
