## 签名与风险

- macOS 当前使用 ad-hoc 签名，未配置 Developer ID 与 notarization。
- Windows 只有在 certificate/password secrets 同时存在时签名；未配置时明确生成 unsigned Squirrel 资产。
- `node-pty` 是 Electron ABI 相关原生模块，必须由 macOS/Windows 原生 GitHub runner 分别完成构建、打包和 Gate B。
- Workspace Terminal、Files 和 Browser 扩大桌面 host capability，必须保留 Project scope、HTTP(S) allowlist、typed IPC 和销毁回收守卫。

## Debug report

- 现象：固定 Codex `0.145.0` 后，Gate B 无法继续证明 command、patch、MCP 和 user input 输出回流。
- 根因：`gpt-5.6-sol` 启用 Responses Lite code mode；顶层只广告 `exec / wait / request_user_input / collaboration`，command 通过 `exec` custom tool 调用嵌套 `exec_command`，延迟 MCP 工具通过 `ALL_TOOLS` 发现，工具结果可以是 `custom_tool_call_output`。旧 fixture 只理解传统 Responses 形态。
- 修复：`scripts/smoke/electron-smoke.mjs` 同时支持传统 Responses 与 Responses Lite，根据实际广告的工具和 output item 路由受控 fixture，并输出 `responsesLiteCodeMode` 及各类工具回流证据。
- 关联收口：共享 Composer 抽取后，App 测试和 Gate B 改为真实“添加 -> 项目”二级菜单路径；`ComposerAddMenu` 保留稳定 `data-testid`，完整 turn payload 覆盖 attachments、capabilities、mode 和 model settings。
- 回归：`App.test.ts` 11 项、全量 Vitest 136 项、独立 Gate B 和最终 `verify:local` 通过。
- 状态：`DONE`。

### GitHub Actions `spawn-helper` 平台误判

- 现象：Ubuntu quality runner 执行 `npm ci` 时抛出 `node-pty spawn-helper 不存在: linux-x64`。
- 根因：准备脚本用“非 Windows”表达 macOS 专用 helper 逻辑；node-pty 的 Linux 实现不需要或携带该 helper。
- 修复：仅在 `process.platform === 'darwin'` 时校验并修复 `spawn-helper` 执行权限；Windows 继续使用 ConPTY/WinPTY 资源，Linux quality 安装直接通过。
- 回归：Darwin 实际执行和模拟 Linux no-op 均通过；最新 `npm run verify:local` 完整退出 0。仍等待重建 tag 后的 Ubuntu/macOS/Windows Actions 证据。
- 状态：`DONE / PLATFORM_PENDING`。

### Windows Gate B 使用 Unix shell 命令

- 现象：Windows runner 的 Gate B 在等待包含 `gate-b-shell-output` 的 `commandExecution` 时超时；此前两条产品 child process 与 provider fixture 均已正常工作。
- 已排除假设：原 fixture 的 `printf`、shell heredoc 与 `sleep` 确实不兼容 Windows，但改为 Node 和跨 shell `echo` 后 command projection 仍缺失；具体命令文本不是完整根因。
- 根因：固定 Codex `0.145.0` 在 Windows 的 code-mode runtime 不注册 nested `exec_command`，但 `gpt-5.6-terra` 的模型目录要求 `code_mode_only`；实际返回为 `TypeError: tools.exec_command is not a function`。这是固定上游 runtime 的已知平台能力边界，不属于 Renderer projection。
- 修复：Responses Lite patch 已直接调用嵌套 `apply_patch` 并获 Windows 证据；Gate B 在 Windows 仍执行并验证一次模型切换，随后显式选择 catalog 中最新的 direct-tool 模型 `gpt-5.5`，验证真实 command、patch、MCP、user input 和 interrupt；macOS 继续验证 `gpt-5.6-terra` Responses Lite/code-mode。
- 状态：`ROOT_CAUSE_FIXED / PLATFORM_PENDING`。
