# LimeShot v0.4.0 发布执行计划

状态：`release authorized / commit and push in progress`
更新日期：`2026-07-29`
基线：`v0.3.0` / `fe144d1`

## 主目标

将当前已闭合的 Windows x64 发布链、Codex Desktop GUI parity 第一阶段、Project 会话树与自动归组、Agent 投影增强、Business protocol v5、仓库治理和 LimeShot 应用图标作为一个完整候选发布为 `v0.4.0`。正式资产只能由 GitHub Actions 在 macOS arm64 与 Windows x64 原生构建；任一平台失败都不得发布半套 Release。

## 当前阶段

版本事实源、发布文档与本地门禁已收口。本地 tag、远端 tag 与 GitHub Release 均不存在 `v0.4.0`；用户已明确确认执行 release commit、annotated tag 和 push。

## 候选范围

### 发布与平台

- npm 与 Rust workspace 版本统一为 `0.4.0`。
- GitHub Actions 增加 Windows x64 原生 Gate B、Squirrel 构建和 macOS/Windows 统一 checksum 发布链。
- Forge、Codex resource manifest、resource provenance 与 supervisor 支持 `darwin-arm64` 和 `win32-x64`。
- SVG 应用图标及 PNG、ICNS、ICO 平台产物接入 Electron 窗口和 Forge package。

### 产品与协议

- Project 会话树、Recent 去重/整理、Project Home、Codex 根 Thread 自动归组与外部 Thread 只读 history。
- Project/Conversation 菜单及 rename/archive/delete/unbind 等具备完整 owner 的操作。
- Business protocol v5 的 Rust、schema、generated client、Desktop Host/preload 和 Renderer 消费者同步。
- Activity Row、MCP/Dynamic Tool/Resource/Media、Multi-Agent、Hook、Context Compaction 与安全脱敏投影。
- Codex Desktop GUI parity 第一阶段及对应 UI governance、Renderer tests 和真实 Electron Gate B 证据。

### 仓库治理与文档

- 根 `AGENTS.md`、`internal/aiprompts/**`、`internal/exec-plans/**` 和四个项目 Codex skills。
- PRD、Codex Conversation 投影与 GUI parity 路线图事实源。
- README 与中英文 `v0.4.0` Release Notes。

## 架构确认

- [x] 产品链保持 `Electron Renderer -> preload -> Electron Main -> Codex App Server + Rust Business Service`。
- [x] Codex native JSONL 与 Rust JSON-RPC 2.0 / JSONL 继续是两套平级协议；Electron 不实现第二套业务后端。
- [x] Agent loop、Thread/Turn/Item 和 canonical history 继续由 Codex 唯一拥有；自动归组只做读取、所有权映射和只读保护，不复制 history。
- [x] Project、binding、Brief、Plan、Task、Provider、Media、Artifact 与 Deliverable 继续由 Rust Business Service 拥有。
- [x] 本候选新增的是平台发布、现有 owner 内的协议能力和 GUI 投影，不改变全局架构，因此无需修改架构图拓扑。

## 签名与风险

- macOS 使用 ad-hoc 签名，尚未配置 Developer ID 和 notarization。
- GitHub repository 当前没有 Windows signing secrets；workflow 将明确生成 unsigned Squirrel 资产。
- workflow 只在 Windows certificate 与 password 同时存在时启用签名，缺一项会 fail closed。
- `v0.4.0` tag 公开后不得改写；后续修复必须使用新版本。
